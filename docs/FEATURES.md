# What Mediarium does today

A plain comparison of what Mediarium does **today** against the apps it can replace or sit beside, written from the source code.

- **Snapshot:** 2026-10-11, Mediarium 3.0.0 (database migrations up to `0170`; see the [changelog](../CHANGELOG.md)). Read every "No" as "not found when this was written". If it matters to you, look in `internal/` and `web/src/pages`.
- **How each row was judged:** Yes = implemented and reachable in the UI or API. Partial = something real exists but it is narrower than the reference app. No = not found. The evidence is a package, file, endpoint or guide you can open.
- **Reference apps** are described from general knowledge of those projects and may be out of date for their newest versions. Uncertain claims are worded loosely or left out.
- Abbreviations: **Rad** Radarr, **Son** Sonarr, **Lid** Lidarr, **Pro** Prowlarr, **Sab** SABnzbd, **qB** qBittorrent, **Baz** Bazarr.
- In Mediarium's screens, indexers are called **Indexers**.

## 1. Where Mediarium stands in one paragraph

Movies, TV, music, ebooks and audiobooks all work end to end (music, ebooks and audiobooks once you switch them on; see 2.4b and [books.md](./books.md)). That covers TMDB metadata; one search across Newznab/Torznab indexers and definition-based torrent sites (the community Cardigann definitions, downloaded on demand); grabbing; a built-in Usenet client (multiple servers, PAR2, native RAR and ZIP unpacking, `7z` only for `.7z`); and a built-in BitTorrent engine (with an embedded WireGuard VPN and kill switch), or a torrent client or debrid service you already use. It also has hardlink import with naming presets, quality profiles with custom formats (and a TRaSH import), delay profiles, upgrade hunting, a blocklist with automatic retry, monitoring, tags, several folders per kind of media, a calendar, a wanted list, import lists that sync on a schedule, a request portal, subtitles, many kinds of notification, media server refresh, family accounts with single sign-on options, backups (also to the cloud), a clean-up of the downloads folder, health checks and a first-run wizard.

What is still thin or missing, stated plainly: files are not unpacked while they download (Usenet downloads unpack when they finish); downloads can't be dragged to reorder; a delay profile is one setting for the whole library (none per title, none for music or books); there are no per-indexer query limits, no per-indexer tags and no category mapping you can edit; there is no Last.fm scrobbling (ListenBrainz works); no comics or manga, no podcasts, and no adult content module; no theme songs or extras; watch state is read from your media server every six hours, not pushed by a webhook; and IMDb and Letterboxd lists are read from the exported file, not synced live (those sites don't allow it). Section 3 has the full list.

Family accounts exist. An administrator can add basic-user and viewer accounts (see [accounts.md](./accounts.md)). RAR (RAR4 and RAR5, including multi-part sets) and ZIP are unpacked natively in Go, so they work the same everywhere. Only `.7z` (also when it is split into `.7z.001`, `.7z.002`, ...) uses the `7z` tool, which the Docker image includes.

## 5. Things that work differently than you might expect

- **Download folders:** each download works in `downloads/incomplete/queue-N` (or `incomplete/<category folder>/queue-N` for a torrent with a category) and is imported straight from there. The `downloads/complete` folder is created but not used.
- **Metrics endpoint:** `GET /metrics` (and `/api/metrics`) is for administrators; a Prometheus scrape uses an API key as a bearer token.
- **Hardlinks and folder mounts:** hardlinks only work inside one mounted folder, so the compose file and every platform guide use one `/data` mount for downloads, movies and TV. Separate mounts copy files instead. See [INSTALL.md](./INSTALL.md#why-one-data-folder-hardlinks).
- **Install methods:** Docker is the only supported install for now. A native Linux program is attached to each release as a preview (there are no Windows or macOS versions; those run the Docker image in Docker Desktop), and the app-store entries are prepared but not submitted ([PLATFORMS.md](./PLATFORMS.md)).
- **Backups:** the in-app backup is the easy way (Settings > System > Backup and restore). By hand, stop the container first, so no download is writing files while you copy them.
- **Tags and folders:** tags keep titles apart on your media server (each tag becomes a collection); extra library folders keep them apart on disk. You can use either, or both.
- **Optional extras are off until you turn them on:** subtitles, music, ebooks and audiobooks, delay profiles, size limits, NFO files, cleanup rules, what's been watched, single sign-on, directory sign-in, IRC announce and import lists all start switched off.
- **Trailers:** the trailer behind a title page comes from YouTube, so YouTube sees the visit. An administrator can switch it off for everyone.
